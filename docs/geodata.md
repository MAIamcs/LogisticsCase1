# Реальные геоданные Новосибирска

География и аналитические значения имеют разные источники. Геометрии в
`contracts/geography/` — реальные опубликованные контуры и объекты. Прогнозные
значения демонстрационного поставщика остаются синтетическими; реальные
геоданные не делают их результатом аналитической модели.

## Десять районов

`districts.geojson` содержит Дзержинский, Железнодорожный, Заельцовский,
Калининский, Кировский, Ленинский, Октябрьский, Первомайский, Советский и
Центральный районы. Источник — областной геопортал, слой
[«Границы районов г. Новосибирск», ID 7](https://maps.nso.ru/arcgis2/rest/services/Common/Boundary/MapServer/7).
Данные получены 9 ноября 2026 года через публичный ArcGIS REST query с
`outSR=4326` (WGS84, порядок координат — долгота, широта).

Исходный ответ сохранён в `source/districts.esri.json`, описание слоя — в
`source/districts.layer.json`. GeoJSON сохраняет все координаты без округления,
упрощения, ручной обводки или подгонки к картинке. Меняется только направление
колец для GeoJSON. Калининский район представлен `MultiPolygon`: отдельный
контур Пашино сохранён, а не соединён вымышленным перешейком. Все десять
геометрий прошли проверку валидности Shapely.

Стабильные идентификаторы — `district-{slug}`, исходный `OBJECTID` передан в
`properties.source_id`. Состав Центрального административного округа не
подменяет три отдельных района: Центральный, Железнодорожный и Заельцовский.

Слой является опубликованной геометрией областного GIS. Дата юридического
вступления границ в силу в метаданных не указана. Нельзя выдавать этот снимок за
кадастровое удостоверение или за самостоятельно проверенную юридическую
редакцию границ. Метаданные слоя не объявляют отдельной открытой лицензии;
лицензия OpenStreetMap не распространяется на этот источник. Атрибуция:
«Геопортал Новосибирской области» со ссылкой на исходный слой.

Приложенный пользователем план развития до 2030 года служит визуальным
референсом. Он не геопривязан, а выделенные на нём территории развития не
являются перечнем десяти районов. Контуры районов не извлекаются из фотографии.

## Дороги, здания, вода, станции

Источником контекстных слоёв служат данные OpenStreetMap из публичного
[регионального extract OsmAnd](https://builder.osmand.net/osm-extract/russia_novosibirsk_asia/russia_novosibirsk_asia.pbf).
Срез получен 9 ноября 2026 года. Контрольная сумма скачанного PBF и описание
каждого слоя сохранены в `manifest.json`; сам региональный PBF в репозиторий
не включается.

- `roads.geojson`: автомобильные дороги и подъезды. `kind` сохраняет класс
  `highway`. Пешеходные тропы, лестницы и полный граф маршрутизации не заявлены.
- `buildings.geojson`: контуры имеющихся в OSM зданий во всём охвате города.
  Это картографические объекты, а не кадастровые сведения или показатели
  вместимости.
- `water.geojson`: полигоны рек и водоёмов, линии рек, ручьёв и каналов.
  Контекстная вода обрезается по охвату фоновых слоёв.
- `stops.geojson`: имеющиеся железнодорожные станции и станции метро, включая
  объекты `railway=station/halt`. Это не полный реестр автобусных остановок и
  не источник пассажиропотока.

Геометрии дорог и зданий не сглаживаются. Фоновые слои ограничены прямоугольным
охватом города, указанным в manifest, и могут включать ближайшие объекты за
административной границей. Аналитическая заливка и выбор района используют
строго контуры `districts.geojson`. Полнота и актуальность конкретных объектов
зависят от исходной базы; импорт не дорисовывает отсутствующие объекты.

Стабильные идентификаторы объектов — `osm-way-{id}`, `osm-relation-{id}` или
`osm-node-{id}`. Они сохраняются в `id`, `feature_id` и `source_id` и доступны
для привязки будущей модели. Имя объекта передаётся из `name:ru` / `name`; для
неназванных объектов не придумываются адреса или маршруты.

Данные OSM распространяются под [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/).
На карте должна оставаться видимая атрибуция
[© OpenStreetMap contributors](https://www.openstreetmap.org/copyright).
Локальный срез и его исходный снимок распространяются с той же лицензией.
Внешние растровые тайлы и API-ключи для этих слоёв не нужны; правила серверов
тайлов OSM не подменяются лицензией на сами данные.

## Воспроизводимость и обновление

`source/osm-context.json.gz` — воспроизводимый сжатый снимок выбранных
OpenStreetMap-объектов с исходными ID и геометриями. `mtime=0` делает упаковку
gzip детерминированной. Обычная генерация требует только стандартную библиотеку:

```sh
python scripts/import_geography.py
python scripts/import_geography.py --check
```

Для намеренного обновления OSM скачайте новый PBF из указанного источника и
установите инструменты импорта в отдельное окружение:

```sh
python -m pip install osmium==4.3.2 shapely==2.2.0
python scripts/import_geography.py --osm-pbf /path/to/russia_novosibirsk_asia.pbf
```

При обновлении измените дату получения и версию в скрипте; пересмотрите
источник и его лицензию, контуры, состав районов, список станций и договор
поставщика аналитики. Обновление границ требует нового исходного ArcGIS query,
сохранения ответа и описания слоя, проверки состава из десяти районов и
топологии колец. Автоматический импорт отклоняет неожиданно изменившуюся
структуру колец, вместо того чтобы угадать новую геометрию.

Публикуются GeoJSON, manifest, источник и документация вместе. Скрипт не меняет
прогнозные значения и не рассчитывает критические интервалы. Геоданные
поставляются независимо от модельного провайдера и доступны в demo и API
режимах из одного набора.

Крупные `contracts/geography/roads.geojson` и `buildings.geojson` генерируются
из версионированного `source/osm-context.json.gz` и не хранятся повторно в Git.
Подготовка: `python3 scripts/import_geography.py` из корня. Frontend-команды
`pnpm dev`, `pnpm test` и `pnpm build` восстанавливают отсутствующие слои
автоматически; для этого нужен Python 3.11+. Содержимое GeoJSON и контрольные
суммы сохраняются без изменения.
